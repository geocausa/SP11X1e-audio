# UbiG de-blob roadmap

## Objective

Deliver a native UbiG userspace DSP path for the SP11 built-in speakers that does not require the two proprietary Windows DSP binaries. The existing Denali `qcadsp8380.mbn` firmware remains a platform firmware dependency and is outside UbiG's de-blob scope.

The current Golden v32 audio path is the protected integration baseline. UbiG develops in `/home/geoca/Documents/SP11-PROJECT/03-UbiG` on branch `ubig/deblob-main` and must not alter Golden boot artifacts or installed production filters until an explicit promotion gate is reached.

## Architecture decision

UbiG is split into three layers from the beginning:

1. **Realtime DSP engine** — pure native C, deterministic, no IPC or allocation in `process()`.
2. **Control transport** — a small versioned shared control page read at block boundaries with request-generation / acknowledge-generation semantics.
3. **Userspace controller** — future `ubigd` service owns persistence and exposes a friendly API to `ubigctl` and a GUI. The controller can later expose D-Bus without coupling D-Bus to the realtime engine.

This directly supports profile switching and a Custom 20-band EQ without restarting the audio engine or losing adaptive history.

### M1 — deterministic oracle corpus

Build a fixed corpus whose inputs are freely generated by UbiG tools:

- impulse / delayed impulse
- DC-safe low-frequency steps
- logarithmic and stepped sine sweeps
- two-tone / multitone / intermodulation probes
- deterministic white/pink-ish noise
- independent L/R probes
- amplitude staircase through limiter/leveler boundaries
- long-history sequences for adaptive-state convergence
- arbitrary host chunk schedules: 1, 64, 127/353, 480, 1024 and chaotic mixes
- in-place profile transitions and Custom EQ transitions

For every corpus item retain reference output, stage-boundary captures when available, state fingerprints and lifecycle metadata. Proprietary binaries are used only to produce private oracle outputs; no proprietary bytes enter UbiG source control.

Exit: one command compares UbiG against the frozen Windows-reference bridge and reports sample error, correlation, state deltas and first-divergence location.

### M2 — UbiG front-end / VLLDP wrapper parity

Replace all non-algorithmic behavior around the first Windows DSP stage:

- 48 kHz stereo format contract
- 432-domain outer scheduling behavior
- 256-frame persistent accumulator
- startup/history latency
- host-chunk invariance
- profile family retune lifecycle
- peak/system control semantics
- endpoint postgain control semantics (**closed natively; exact Stage-A runtime lane 1**)
- no reset on ordinary PipeWire activate/idle transitions

During M2 the algorithm callback may still be an oracle adapter in test binaries only. Production remains untouched.

Exit: wrapper/state-machine behavior is native and bit-exact independent of host chunking.

### M3 — native UbiG first-stage DSP

Replace the first proprietary DSP algorithm incrementally. Work by stage, not by whole-DLL approximation:

1. input/staging and analysis path
2. audio optimizer/filterbank behavior
3. regulator path
4. multiband compressor path
5. leveler-related state used by this stage
6. final limiter and peak-level semantics
7. profile-dependent state/application ordering

Each stage must have a differential oracle and a documented behavioral specification before implementation is accepted.

Preferred target: Movie first, then Music, then the common Dynamic family.

Exit: UbiG first-stage output/state passes the frozen oracle corpus while the second Windows stage remains behind it only in a private lab hybrid.

Current checkpoint: the SP11 48 kHz Stage-A scheduler is native and reaches the public engine API for all seven profiles. A private whole-chain hybrid now substitutes this public engine for the Windows VLLDP stage and remains bit-exact through fixed-profile, deterministic transition and randomized long-history tests. The VLLDP DLL is not loaded at all in that hybrid, so M3 algorithm/runtime replacement is complete for the shipped endpoint. Remaining work is Stage B / VR construction and control de-blob.

### M5 — control service and application

**2026-08-22 engine-control slice complete:** `ubig-control` 0.1.0 packages a
GTK4 profile/20-band GEQ application plus the native `ubigctl` fallback. It
uses the existing v2 request/ack page directly, applies without a graph
restart, displays engine acknowledgement and persists the selected profile and
Custom curve per user. The installed package passed a live same-profile
request/ack gate without PID or fault drift.

This is sufficient for ordinary engine use. A sole-owner D-Bus service and an
explicit bypass ABI remain optional control-plane expansion, not missing DSP
engine semantics and not prerequisites for acoustic/soak qualification.

Implement `ubigd` as the sole persistent control owner:

- profile: Dynamic, Movie, Music, Game, Voice, Course, Custom
- Custom 20-band EQ
- enable/bypass
- future advanced controls only when they have stable native semantics
- persistent per-user state in XDG config/state directories
- request/ack/error/status reporting
- no DSP restart for ordinary profile/EQ changes

Expose a stable service API; D-Bus via GIO is the preferred desktop-facing transport when implemented. `ubigctl` becomes a client of the same service. A GTK/libadwaita GUI can then be added without touching DSP internals.

Only after these gates pass may the installed Windows-binary bridge be removed.

## Non-goals

- replacing `qcadsp8380.mbn`
- cloning every product feature of the Windows software stack
- reproducing unused spatial or capture paths
- matching compiler implementation details where an independently specified equivalent behavior is sufficient
- shipping private oracle fixtures or proprietary binaries

Stage-B dependency closure now also includes the exact post-controller 17-float scalar curve builder/evaluator pair; work continues upward through the remaining direct children of the Leveler producer.
