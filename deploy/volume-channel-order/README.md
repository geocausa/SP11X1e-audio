# SP11 Windows channel-ordered volume candidate

Date: 2026-08-14 (Europe/London)

## Scope

This is an isolated one-shot extension of the accepted
`7.1.5-sp11-render-parity-v4+` boot. It changes only `snd-q6apm` in the candidate
initramfs and the backward-compatible userspace volume synchronizer. The v4
kernel image, DTB, installed module tree and persistent CPS-v3 fallback are not
modified.

Fresh SP11 Windows KDNET proved that one stereo endpoint master-volume gesture
is delivered to qcadcm as two channel-ordered SetVolume calls:

```text
upward:
  L=new, R=old -> mixed-state GainStep
  L=new, R=new -> final GainStep

downward:
  L=new, R=old -> mixed-state GainStep
  L=new, R=new -> final GainStep
```

The mixed-state GainStep is the louder of the old/new per-channel states. The
same capture proved final `VOL_CTRL 0x4a63/0x08001038` precedes GetGraphCkv and
the dependent `0x489e` calibration on each call. VLLDP postgain does not update
on these live gestures and is now frozen for one Dolby/filter-chain generation.
See `docs/findings/2026-08-14-WINDOWS-LIVE-VOLUME-LIFECYCLE-KDNET.md`.

## Kernel delta

Canonical patch:

```text
patches/0054-ASoC-q6apm-match-Windows-channel-ordered-volume.patch
```

The patch:

- changes the fixed final-volume helper to accept independent left/right Q28;
- extends `SP11 Windows Volume Transaction` from a 284-byte to a 288-byte ALSA
  bytes-TLV capacity;
- accepts `left_q28 + right_q28 + GainStep delta` as the new exact form;
- preserves the deployed one-Q28 ABI for rollback userspace;
- keeps final VOL_CTRL fixed at iid `0x4a63`, pid `0x08001038`;
- keeps the existing strict four-frame `0x489e` GainStep validator unchanged;
- exposes no arbitrary new module/parameter target.

Strict kernel checkpatch: `0 errors, 0 warnings, 0 checks`.

## Userspace capability gate

`sp11_windows_volume_transaction_sync.py` reads the ALSA control capacity once:

```text
values=284 -> legacy-stereo
values>=288 -> windows-lr
```

Thus the new userspace is safe on the accepted v4 boot. On the candidate,
ordinary master changes are sent as two existing-style atomic calls. The host
sink moves to unity only after the complete sequence succeeds, preserving the
fail-quiet handover.
