# SP11 recovered7.1 UCM dependency restoration: physical gate

On 2026-10-30 the owner confirmed **two clear normal volume-slider checks after quiet pauses**, following a fresh boot of exact recovered `7.1.5-sp11-render-parity-v4+`. Both `WSA WSA_COMP1 Switch` and `WSA WSA_COMP2 Switch` were on after boot; deployed SP11 profile SHA256 is `ed8524e86bd9bef11639f99da920fce792eb42898738e1956a2a0745bdd2def6`. Implementation commit: `29f0008fab43affb33b6d195ef55202e2e54e687`, parent14d3651. The owner also confirmed touch works, correcting an earlier accidental negative selection; passive counters show1796 Heat frames/1517 output contacts, zero Heat/transport/protocol errors.

Before the restoration, every first slider movement after teardown popped. A continuously open stream's later sounds were clear. Separate PCM starts popped even while SoundWire/WSA remained powered. Gain-policy trials did not produce a reported improvement. The SP11 profile itself matched the USB backup, but its transitive packaged Wsa1SpeakerEnableSeq include changed: old stock package enabled both macro companders, new stock package omitted them. Both files matched their respective package checksums. Archived saved ALSA state also had these macro controls on.

This board-specific profile pins the archived state before ACP's first protected PCM probe. The generic distribution include is unchanged. Separate speaker-codec COMP switches are not these macro controls. Golden-wrapper plugin, normal volume helper, full protected topology, calibration, firmware, and current PipeWire1.6.8/WirePlumber0.5.17 are preserved. No always-on stream, new fade or guessed register write is used.

Counterevidence: [upstream ALSA UCM6174717](https://github.com/alsa-project/alsa-ucm-conf/commit/61747175343afaf0749b91d9f323fa4a0405a901) deliberately removed these enables due incorrect compander behavior and attack distortion on some X Elite platforms. The positive result here applies to the custom recovered SP11 kernel/board; it does not justify restoring them globally. Earlier on/off/off/on tone comparison was inconclusive, so the new result supports a practical fix in this tested setup, not exclusive causal proof.

Scope: fresh-boot persistence plus two ordinary cold slider checks and touch. Long-term/content-wide behavior, microphone, cameras, system suspend, and the7.3 port remain unqualified. Full private evidence and transitive include manifests are maintained in the local SP11-Unified-Kernel project; proprietary payloads and per-unit identities are excluded from this source note.
