## Status

## Exact scope

The candidate changes only `snd-q6apm` relative to the accepted CPS-v3
initramfs. It adds fixed-target ALSA bytes control
`SP11 Windows Volume Transaction`. The kernel validates a userspace payload as:

- one Q28 gain at or below unity;
- exactly four ordered iid `0x489e` frames;
- pids `0x08001020`, `0x08001021`, `0x08001022`, `0x08001026`;
- exact 216-byte or 272-byte total size and zero alignment padding.

On a running protected graph it sends the exact 104-byte final
`0x4a63/0x08001038` volume body first, followed by the complete GainStep delta
through the existing OOB graph-calibration mapping. Arbitrary module targets,
malformed payloads and idle graphs are rejected.

Userspace ordering is Dolby postgain, combined DSP transaction, then hardware
sink unity. While idle, on failure and on service exit it establishes/restores
host attenuation. The dispatcher detects the candidate ALSA control; rollback
kernels automatically exec the established legacy volume actuator, and the
separate legacy MSIIR service stands down only when the combined control is
present.

## First live-gate result and mandatory correction

The first one-shot boot reached the intended entry, loaded candidate
srcversion `7807B09DF71E80C7743045B`, exposed the new ALSA control, retained
working Wi-Fi, and reached protected `GRAPH_START`. Two issues were found:

1. The combined synchronizer could not import extensionless helpers installed
   under `~/.local/bin`. An explicit Python source loader fixes this; a new
   installed-path regression test covers it.
2. A 15% / GainStep-1 216-byte transaction succeeded. During a live
   15->25->40->25->15% sweep, 25% / GainStep-3 272-byte transactions returned
   `-EINVAL`, while 40% / GainStep-12 216-byte and 15% / GainStep-1 216-byte
   transactions succeeded. The userspace fail-safe restored host attenuation
   for every rejection. No failed transaction moved the hardware path to
   unity.

The 272-byte rejection was local kernel truncation, not a DSP rejection:
`SND_SOC_BYTES_TLV` limits the callback's complete buffer including its
8-byte header. Patch `0048` supplied a maximum of 276 instead of 284 bytes.
Patch `0049` corrects that arithmetic without changing accepted transaction
bytes. The corrected module/initramfs above has passed build, signature and
initramfs-isolation checks and replaces the isolated test boot image. A second
one-shot reboot is required to validate the large rows.
